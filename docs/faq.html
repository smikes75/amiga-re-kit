Questions and answers

Is this an emulator or a port?

Neither. The game's own 68000 code from your disks is translated ahead of time into C and WebAssembly (static recompilation) and runs natively in the browser. The Amiga chipset, bus timing, Copper, Blitter, bitplanes, sprites, Paula, is a model checked against the vAmiga emulator. No processor is emulated at run time and no game logic has been rewritten by hand.

Why not just use an emulator with a variable-refresh (VRR) monitor?

VRR removes the judder of 50 Hz on a 60 Hz screen, and for the Original mode that is a fine solution. But the game's main loop still moves its objects 25 times a second (the camera 50) and the window is still 330 pixels wide. The Enhanced mode interpolates the camera and the objects between game frames and draws a wider view from the game's own data, which no emulator setting can do.

Does the Enhanced mode add input lag?

Smoothing needs the next game frame before it can draw the step in between, so the picture is drawn a little behind the game: the camera about 30 ms, the objects about 40 ms. Measured on the current build with the kit's tool in headless Chromium (a key event dispatched in the page until the camera moves): about 80 ms. The version on this site cannot use the faster engine thread, because GitHub Pages does not send the headers it needs. A side-by-side measurement against a real Amiga is on the list.

Which disk images work?

The commonly preserved dumps of the Amiga 500 version (the Fairlight release, with and without trainer), disks 1 and 2 as .adf; the page unlocks by the game's files on the disks, not by one exact image. An original retail disk has not been verified yet: if you own one, please write to me. The AGA version is not supported. The page tells you when a disk is not recognised. Does the page contain the game?

No game data: no graphics, levels, music or code listings. The code derived from the game and its start state are encrypted and unlock only with a key derived from your own disks. Your disk images are checked in your browser and never uploaded.

What exactly does the AI do?

It drives the kit: reads the disk, finds the loader and the packers, translates routines, runs the rebuilt code against the original in an emulator and compares memory, picture and sound. The rule is measure, never guess: nothing is accepted that is not equal to the original. The AI does not generate graphics, levels or code of its own; everything on screen comes from your disks.

Is this legal? What about Team17?

Alien Breed II and Superfrog belong to Team17. AREK is a free fan project that ships no game data, no disk images and no Kickstart ROM; you need to own the game. If you represent the rights holder and have any concerns, please write to me first; I will respond.

AREK is free and open source (MIT) and ships no disk images, no Kickstart ROM and no game data. It measures games through the vAmiga emulator by Dirk W. Hoffmann; the kit carries small patches to it (MPL-2.0), not the emulator itself.

Alien Breed II and Superfrog belong to Team17. The playable page holds none of the game's data: you supply disk images of a game you own, and the code derived from the game opens only with them.
